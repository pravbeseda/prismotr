# Spec: Configuration

- **Status:** approved 2026-10-16 (reviewed and in force)
- **Owns:** `internal/config`: the file ansible-hosts writes, its validation, and the
  configuration in force while the daemon runs
- **Decisions:** the contract in ansible-hosts, `.github/tasks/task12-prismotr-panel.md`,
  section *The configuration file*; the plan's decisions on `logs`, `hub_url` and menu order

## Purpose

The daemon reads one YAML file, `/etc/prismotr/prismotr.yaml`, and turns it into the host
and the list of sites every page renders. The file is written whole by ansible-hosts on
every run; the daemon never writes it, never fills in what it does not say, and never looks
anywhere else for what is attached.

It does not decide how the menu is ordered or grouped — that is the sites page in
`internal/web` — and it does not read any host state.

## The file

```yaml
host: host-a                               # required: the inventory name
domain: host-a.example.com                 # optional: the host's own name
base_path: /prismotr                       # required: "/" or "/<segment>", no trailing slash
hub_url: https://hub.example.com/nodes/host-a   # optional: rendered as given
sites:
  - name: munin
    kind: location
    title: Munin
    path: /munin
    order: 20
  - name: shop
    kind: vhost
    domain: shop.example.com
    aliases: [www.shop.example.com]
    cert_domain: shop.example.com
    logs: [/var/log/nginx/shop-access.log, /var/log/nginx/shop-error.log]
    php_fpm_versions: ["8.4"]
    order: 50
```

The repository ships `prismotr.yaml.example` with these synthetic values; the real file
lives on the host.

## Behaviour

### Loading

| Given | When | Then |
|---|---|---|
| the file above | the daemon starts | `host`, `domain`, `base_path`, `hub_url` and both sites are in force with every field as written |
| no file at the path | the daemon starts | it refuses to start, naming the path |
| a file that is not YAML | the daemon starts | it refuses to start, naming the path and the parse error |
| a file without `sites`, or with `sites: []` | the daemon starts | it runs with no sites |
| a file without `host` | the daemon starts | it refuses to start, naming `host` |
| a file without `base_path` | the daemon starts | it refuses to start, naming `base_path` |
| `base_path: /` | the daemon starts | it runs with `base_path` `/` |
| `base_path: prismotr` (no leading slash) | the daemon starts | it refuses to start, naming `base_path` |
| `base_path: /prismotr/` (trailing slash) | the daemon starts | it refuses to start, naming `base_path` |
| a site with `kind: proxy` | the daemon starts | it refuses to start, naming the site and the kind |
| a site without `name` | the daemon starts | it refuses to start, naming the position in the list |
| a `location` site without `path` | the daemon starts | it refuses to start, naming the site |
| a `vhost` site without `domain` | the daemon starts | it refuses to start, naming the site |
| a file with a key this version does not know, at the top level or in a site | the daemon starts | it runs, and the unknown key is reported on its log, named with its site where it has one |

### Reloading

| Given | When | Then |
|---|---|---|
| a running daemon and a file that now lists one more site | `SIGHUP` | the next page shows the new site |
| a running daemon and a file that now fails any row of *Loading* | `SIGHUP` | the daemon keeps the configuration in force, logs the error, and the next page shows the sites it had |
| a running daemon and a file that was removed | `SIGHUP` | as the row above: the configuration in force stays |

## Invariants

- What is in force is always a whole file that passed every row of *Loading*: a page never
  renders half a reload.
- A site's `order` defaults to 0 and its lists (`aliases`, `logs`, `php_fpm_versions`) to
  empty; no other field has a default.

## Edge cases

- `base_path` is compared as written: `/Prismotr` and `/prismotr` are two paths.
- Two sites with the same `name` are not refused: the name is the contract's identifier,
  and the file is generated by one template from one inventory, so a duplicate is that
  template's bug, visible on the page, not a reason to take the panel down.

## Out of scope

How the sites are ordered and grouped on the page, and what `Main Site` links to — the
sites page. Where the listen address comes from — the command line and `PRISMOTR_LISTEN`,
owned by `cmd/prismotr`. Reading any state of the host.
